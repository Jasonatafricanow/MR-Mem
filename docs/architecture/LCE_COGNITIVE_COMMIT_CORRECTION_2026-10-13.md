## 3. 核心纠偏：LCE 管结构与演化，不是真理认证器

**对象**：一份认知在某个时间/作用域下如何被主体组织。LCE 保存当时的判断、条件、行为、推论、相互关系和后续的演化，而不判断这些主张是否客观正确。

区别：

| 必须做到 | 不属于 LCE 的权限 |
|---|---|
| 忠实保留“当时我认为 X”的认识状态 | 把“我认为 X”偷偷提升为“世界客观事实 X” |
| 提炼原文里已经表达的逻辑结构 | 评判用户的交易判断在现实中是否最优 |
| 保留来源、时间、作用域、关联与修订 | 要求额外独立来源才承认用户确实持有这种认知 |
| 对原文未表达的联系保持推断边界 | 凭借模型推测伪造用户的观点或原始证据 |
| 支持后续修订、分叉、回滚、合并 | 让最新版本把此前认知从历史中抹去 |

例子（**示意结构，不是用户文章逐字文本**）：

```text
认知：单日放量突破，不足以单独授信结构反转
  ├─ 观察：单日放量/价格变化
  ├─ 判断：一个局部信号尚不足以形成确认
  ├─ 条件：仍需验证更长区间的价格结构
  ├─ 决策：当前不建立仓位
  └─ 后果/意图：限制错误突破下的敞口
```

编译验收问题是：“**这是否忠实表达了用户当时文章中陈述的逻辑关系？**”而不是“**这个判断在市场上是否绝对正确？**”

“真实性”仍有具体且有限的工程含义：Raw 必须确实存在、来源引用真实、编译不能编造原文没有的事实或将推测写成用户原话。它**不等于**认证用户关于世界的认知结论正确。

## 4. Git 机制是认知版本/结构机制，而不是比分数高低的评级表

用户明确使用 Git 类比：

- **Commit**：某时某个认知状态已经形成，可保存为一项可追溯的认知结果。Commit 存在不意味着命题正确。
- **Parent / ancestry**：本次理解从哪个历史结构继续演变；它是版本继承，**不自动等同语义/证据依赖**。
- **Branch**：可以基于旧认知产生不同方向的后续理解；分支可以并存，不必立刻判定哪条是“真”。
- **Diff**：能看见哪些条件、机制、行动原则变了。
- **Rollback**：可以选择再次采用一个历史认识状态，但历史上后来形成过的观点仍可审计。
- **Merge**：把相容或已协调的结构组合成新的认识结果；并非用最新文本覆盖全部旧历史。

```text
t1：文章 A，形成认知 Commit C1 / Line L1
        ├── t2：新经历 B → C2（修正条件）
        │                 └── t3：C3（进一步形成操作原则）
        └── t4：从 C1 开另一条分支 C4
                        └── 后续可能 merge、rollback 或停止维护
```

**注意**：Git 是用户指定的模型/机制类比，不意味着“每篇文章必然映射到 LCE 当前代码某一个 `Baseline` row / revision / HEAD”或“现有 LCE 已提供真正 Git 的每个操作”。必须核对当前 `Line`、`Worktree`、`Baseline` 契约后设计映射。禁止用类比偷换实际代码能力。

## 5. Raw → Canonical SemanticBlock → 可复用逻辑结构

```text
原始单篇长文 Raw Text A（唯一实际文本来源）
          │  SourceRef / 原文身份 / 时间
          ▼
Canonical SemanticBlock（保留整篇语境与原意）
          │
          │  可对内部已明示的逻辑作结构解析
          ▼
逻辑节点：观察 / 条件 / 机制 / 判断 / 行为 / 后果
          │      ↕ 已表达的关联、方向、适用范围
          ▼
LCE Line / 认知 Commit 的结构表示（待与现有契约对齐）
          │
          ├── 以后与其他来源的结构发生延伸、修订、分支、跨领域连接
          └── 可追溯 → SemanticBlock → SourceRef → 原始文章 A
```

这里有三条不能混淆的原则：

1. **语义完整性 ≠ 不可分解性。** SemanticBlock 的完整性用来避免断章取义；LCE 可以从完整 Block 中解析多个内部逻辑组成部分，再尝试与其他 Block 的逻辑连接。
2. **多个逻辑节点 ≠ 多份证据。** 一篇文章可以生成许多节点或多条 Line，但来源仍是原始文章 A。不要制造第二篇文章、额外交互、虚构 Raw 记录去凑支持数。
3. **结构可被保存 ≠ 客观命题被证明。** 此时的 Line 代表作者当时表达的认知；下一次作者修正它，就形成新的结构状态与版本关系。

例：长文中「条件 X → 判断 Y → 行为 Z」应保留 X、Y、Z 的具体语义和方向，不可只抽象为“理性决策”。这样后续跨领域结构才能比较真实机制，而不是靠同一类空泛标签制造假相似。

**暂不强制 SemanticPoint**：Body/Batch 可以直接给出上下文完整的 SemanticBlock。内部结构解析不等于恢复必须先产 SemanticPoint 的旧流程。

## 6. 双交互门槛：历史规则的适用范围需要重新表述，不是加一个布尔开关

**历史事实**：2026-09-26 的 [ADR-0033](https://github.com/Jasonatafricanow/Mind-Runtime/blob/e12ec9418a8/docs/adr/0033-layered-memory-projection-authority.md) 对 Thread maturity 写了至少两个不同 admitted interaction 身份，同一次交互产生多个 Memory 不构成独立支持；这是真实存在的旧约束。9/28 补充明确 Path A 的成熟 Thread 经 `PrecomputedDraftInput → Worktree → Baseline`。

**本次新意图**：对**作者已在单篇文章里完成自洽组织的认知结构**，不能强制它先成为未成熟 Thread，再等待一段与内容没有必要关系的第二次交互。一个长篇成品可能一次就足以产出可用的认知结构/Line。

这两点需要通过 **范围分离** 而非简单地 `min_support=2 → 1` 来处理：

- **未成熟、尚在跟踪的 Thread**：保留历史的独立交互约束，直到正式 ADR 明确改变它的契约；多条 Block 不得冒充两个交互。
- **单篇已完整表达的认知**：允许研究**从原文完整语义直接结构编译、保存当时认识状态**。不以第二份外部文本认证其“真实/成熟”。这不等同于授权生产者对任意零散输入设置 `semantic_maturity=True`，也不意味着所有单篇文字一律都有已形成的 Line。
- **若现有 LCE 只能通过 Thread→Path A 或 Path B 承载上述内容**：先把无法表达之处列为契约缺口，结合原始 `Line/Worktree/Baseline` 的实现选择最小兼容改动，**不要未经调查就发明 Path C、新事实库或全能成熟裁决器**。

ADR-0033 尚未因本文件自动失效；下一轮的正式 ADR 修订应明确两类输入及其适用边界，而不偷改旧代码对 Thread 的成熟约束。

## 7. 与现有工程和 PR #18 的关系（重要注释）

从当时架构资料可以确认：

- **Path A**：已经在线理解的 Thread，直交 LCE 的 `PrecomputedDraftInput → LCE Worktree → Baseline`。现有 Mind-Runtime 的 `LceThreadProjectionCompiler` 是可审计的参照实现。
- **Path B**：为未在线形成的关系做潜在发现；`MrMemProjectionRuntime` 是 LCE Canonical Block 投影路径的一部分，不能因本次不接 Path B 就绕开全部既有权威边界。
- **统一历史读权威**：对外由 Memory composition 选择当前有效的 Baseline、Thread、Canonical 内容，而不是让 Answer 随意组合几个平行存储。
- **Raw / Canonical / Line**：投影可以持久化，但不能成为第二个事实权威；正常读不应每次重播 Raw。

PR #18 的问题是**实现偏离**（自建事件回执/证据累计状态机、双通道 Search、任意 `semantic_maturity` 等），与本次发现的**概念缺口**（高密度单篇认知的内部结构编译）并非同一项工作。**不要在旧 PR 上打补丁来“顺便解决”新认知问题。**

同样，原有 LCE 的 `Baseline` 主要是整段内容加支持 ID；已有的 `DependencyInvalidator` 不等于实现了逐 claim 的局部失效。若提出局部回滚或精细依赖，需要明示为后续功能，不能把一份解释文档当作已通过测试的能力。

## 8. Claude 下一轮审计/实验边界

先做只读对照，**不根据本文件自动大规模重构**。请按「已确认历史设计 / 用户最新意图 / 仓库已实现能力 / 尚未实现或存在冲突」四列检查：

1. **表达能力**：LCE 目前的 `Line` 是否能包含一篇高密度 SemanticBlock 内部显式的条件/行为/后果结构？若只能做外部 Block 间发现，缺什么最小接口？
2. **时间与版本**：Line、Worktree、Baseline 哪个可以实际承载 commit/parent/branch/rollback/merge？哪些只是类比、没有实现？记录 `occurred_at` 与 `known_at` 的不同。
3. **证据方向**：一篇 Raw 文章 → Canonical Block → 其内部多个结构节点/Line，能否逐级溯源？不能制造多个独立 SourceRef 来满足阈值。
4. **历史认知 vs 真理判断**：新增文章与旧观点相矛盾时，能否保留两种历史认识、分别说明作用域和时间，而不是让 LLM 宣布旧观点“错误”？
5. **最小能力实验**：选一篇真实、长且高密度的自写文章，保持原始 SemanticBlock；只判断能否忠实提取具体逻辑并与另一个 Block 连接。严禁 gold 问题泄漏、LLM 暴力全量重读掩盖索引成本；严禁以测试通过宣称完全支持 Git 式认知操作。
6. **Path A 测试基座**：恢复原 Mind-Runtime 中已经存在的真实 Thread→LCE→统一 Memory 出库机制，与单篇文章内部结构研究**分开验收**，避免 Path B 未完成阻塞 Path A。

### 最小验收示例（示意，不是现成测试通过）

- 单篇完整文章 A 形成数个结构节点和 Line：所有节点的源引用仍回到文章 A；无额外伪造独立来源。
- 以后文章 B 改变了某个条件：C1 仍可用于历史审计；当前结构可产生 C2 或分支；系统不判断 C1/C2 哪个代表客观真理。
- Raw A 不可用时：不能声称 A 的原始表达仍然可追溯；派生投影按当前已有生命周期/失效契约做保守处理，不臆造原文或新证据。
- 用户只给一个零散未完成想法：不因为“单次输入”或生产者一个布尔值就自动编译为已完成的结构。

## 9. 交接结论（务必保留）

> **LCE 是认知结构与历史演化的编译/版本系统，不是验证用户观点真伪的认证机关。高密度单篇原文可以本身就表达一份完整的认知 Commit，其内部逻辑可结构化为 Line；Line 的原始证据仍是这一篇 Raw 文章。保留 SemanticBlock 的上下文完整性，同时允许结构分解与后续跨来源连接。把双交互门槛限定在原先所规范的未成熟 Thread 生命周期，不能把它扩大为一切认知进入 LCE 的前提。Git 的 commit、branch、rollback、merge 是预期能力类比，不能把尚未实现的能力写成已经交付。**

**下一步不是认知真理认证、不是增加全能判定权威、不是恢复强制 SemanticPoint，也不是引入未验证的新通道；应先把现有 LCE 结构契约和原架构做能力审计，再用小范围真实材料检验“单篇文章内部结构编译”是否可行。**
