# 研究开发日志

MR-Mem 从 2026-09-29 开始独立开发。这份日志按时间记下每个阶段做了什么、定了什么、放弃了什么、为什么放弃。设计的权威文本在 [LCE_FROZEN.md](LCE_FROZEN.md) 和 [LCE_DESIGN.md](LCE_DESIGN.md)，实测数字在 [TECHNICAL_REPORT.md](TECHNICAL_REPORT.md) 和 [CONFIG_GUIDE.md](CONFIG_GUIDE.md)，这里只写主线和取舍。

## 一条贯穿始终的原则

**原文是唯一权威，其余都是投影。** 编译出来的语义块（SB）、Line、段，都是对原文的理解，可能有错、可以修正，每个投影都要能沿索引追回原文。**推理过的不再推理**：对话发生时已经理解过一遍，编译只是顺带留下这次理解，读出时交出编译产物，而不是把大量原文丢给答题模型重新理解。后面几乎每一次取舍，都是在回到这两句话。

## 时间线

### 09-29 从 Mind Runtime 抽出来（PR #1）

MR-Mem 起源于 Mind Runtime 的记忆子系统（`main@18d9275`）。第一天把 MemoryCore、存储、投影、产品层逐个文件抽出，补齐测试和 CI，把 Memory 的写入、检索、Thread 归属迁进 MR-Mem。

### 10-01 冻结边界（PR #2、#5）

- **ADR-0001 sidecar 边界**：MR-Mem 不替代宿主的会话库。宿主已有持久历史时，原文权威留在宿主，MR-Mem 只持有编译出的语义记忆和派生的 Thread / LCE。
- 热启动清洗和 LCE 投影语义一起冻结。

### 10-02 Semantic Delta V1（PR #6–#11）

宿主通过 SourceRef 把已经接受的语义交给 MR-Mem：先定契约和严格校验，再做确定性闭包、原子写入、读取和冻结任务的恢复。PR #7–#11 合入；PR #6 是同一方向的早期版本，大部分内容已在后面几个 PR 里，没有单独合入。

### 10-03 canonical 投影，以及一次没有结论的 Point 实验（PR #12、#13、#15、#16）

- M1 / M2：只读的 canonical SB 投影视图，消费方可以持久登记，SB 变动时重新排队（合入）。
- PR #15 锁定了"每轮一个 Point、实时窗口一个 Block"的编译架构和 V2 实施计划；PR #16 按这个架构做了 Point 侧车的对照实验，结论是 **NO-CONCLUSION**（上下文快照复位前后无法分出差异）。之后的设计把 Point 定为"当轮理解的副产品，只给 MR 本体用、不进 LCE"，LCE 只吃 SB。这两个 PR 没有合入。

### 10-09 生命周期时间（PR #17）

失效时间写进记录，按某个时间点回放生命周期时能看到当时的状态（合入）。

### 10-13 Path A：先重造、被审计、再移植（PR #18、#19、#20）

- PR #18 从零写了 canonical → Thread → LCE 和 Search 接口，局部 CI 通过；独立审计发现它重造了状态机、扩大了 Thread 的支撑累积、拆散了统一的读权威。随后发现 Mind Runtime 在 9 月已经实现了成熟 Thread → Path A 的组合。**结论：移植已有架构，不再重新发明。** PR #18 放弃。
- PR #19 记下当天的一次纠偏：一篇自写的长文、一份交易心得，可能本身就是已经成形的认知成果，不应只当成一个过于完整的 SB，也不应机械地要求"第二次交互"才算数；验证结论真假不是 LCE 的职责。这份记录的要点已经写进冻结定义和设计稿。
- PR #20 移植了宿主中立的 Path A 核心，作为 AML 分支的基础。

### 10-13 – 11-02 AML 2026 第二轮

[AML](https://github.com/Jasonatafricanow/MR-Mem/tree/feat/aml-20261013) 只比记忆系统本身：平台调用 Add 写入对话，再按题调用 Search，用平台锁定的模型答题、评分。我们给自己定的门槛是：**在开放数据上不能稳定胜过 P1（原文 BM25 + 向量 + RRF），就不参赛。**

- **10-14 – 10-16 定义 LCE。** Thread 在事情结束时成熟，不是"交互两次"；只有两条时间轴，都是消息的时间，内容里说到的时间是内容；只有一种 Line 结构，Thread 和 Path A 是晨昏线两侧；SB 跨多个 turn，是避免断章取义的最小完整意思，一条消息可以分进几个 SB；工作场景和聊天场景的 SB 装的东西不同。设计稿从 v1 迭代到 v8，编译提示词从 v3 到 v9。
- **10-26 读出第一版。** 原文命中 → 按索引找到 SB → 沿 Line 展开，加上原文片段。开发对话 29 题：18.0，高于原文检索 15.5、只给 SB 14.0。
- **10-31 定版。** 按话题切 SB，再切段、给收口的段写一次摘要；读出带段摘要和它的首尾位置；每条原文命中带出它的 SB（`hit_anchors`，58.5 → 60.1）。一批服务端加固：Search 里不在主线程算向量、重启后续编、每用户编译上限。
- **11-02 正式评测完成**：配置 `preview-1029`，31 小时 39 分，中途 7 次中断后续跑，编译约 ¥130、向量约 ¥5，**平均 54.37**。分项和复盘见技术报告 §4.1、§5.1。这个分数既不能证明 LCE 不行，也不能证明它比 P1 强：同一套题上没有 P1 的成绩，平台也不给逐题结果。按比赛规定，复盘只用本地公开数据，不碰评测数据。

参赛版本冻结在 `feat/aml-20261013`。

### 10-22 – 10-23 原生装配（PR #21，没有合入）

把 MR-Mem 装进 Mind Runtime 的工程线，在隔离副本里做：没接编译器也能跑（只存原文、可检索，健康检查报 degraded）；`NativeMemory` 让宿主保管消息，MR-Mem 只存来源引用、批次和编译结果，原文改动或删除会让对应的 SB 失效；把 Line 读出开放给 MR。方向和 ADR-0001 一致，但它基于 10-16 的代码，之后 AML 线上的运行时、编译器、原文检索都大改过，合并代价太大。**放弃这条分支，以后接 MR 时按当时的代码重做**，原实现保留在归档标签里。

### 11-02 – 11-08 赛后：三项测出增益的改动（已进 `main`）

1. **SB 顺着连线带出。** 检索找到的 SB 带上它投影的原话，命中的原文挂在它所属的 SB 下面。BEAM 100K 留出集上，标准证据以原话出现在读出里的比例 51.8% → 89.4%（P1 前 100 条为 79.4%）。
2. **时间戳植入。** 读出里的时间一律带年份；编译时，相对时间（"昨天""上周"）旁边写上对应的日期。LoCoMo 小集重编后，29 个带相对时间的 SB 有 28 个写上了日期（改写提示词之前，23 个一个都没写）。
3. **精准读出（11-08）。** 只有检索真正找到的 SB 带原话，沿 Line 补进来的步骤只给一行；段摘要只给这些 SB 所在的段，不再按相似度另取 60 条。开发集 29 题 37.1 → 43.1，两遍答题都稳定；BEAM 每题读出 10.5 万 → 6.7 万字，需要的信息基本没丢。

这期间也有没测出增益的：块号编进 SB、整份读出预算、会话日期只写一次、短历史全给、段摘要往下找、全局提纲。它们有的删了，有的留作默认关闭的开关，依据都写在配置说明的"试过没采用"一节。

### 11-08 起 `dev`：精准召回

目标是读出里只放和问题有关的东西，又不能为了去噪把真正相关的砍掉。每一步的数字在 `dev` 分支的配置说明里，这里只记方向：

- 原文命中不再固定取 30 条，按"不低于最高分的几成"截断：话题杂的历史能分清噪音，同一话题的历史分不开。
- 长消息按段落建索引，命中只挂命中的那一块；按共用词机械删段的做法放弃了。
- 决策模型给每条命中打分：只能砍最低的一头，门槛一高就会卡掉答案。
- 按设计让原文和 SB 两路在 SB 上合并打分，再沿结构取原话：方向对，同一话题的历史里仍有一处要改。
- 下一版编译：把人转述、转发的文字和人自己的阐述分开。

这些都是默认关闭的开关，分数还在噪声范围内，没有进 `main`。
