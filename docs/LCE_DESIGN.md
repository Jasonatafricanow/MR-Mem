## 0. 要解决的问题

**目标：知道就是知道，不知道就是不知道。不知道是一种合法状态，不是缺陷。**

| 状态 | 含义 | 例子 |
|---|---|---|
| 有证据 | 原文里说过，当前有效 | "我住在里斯本" |
| 过时 | 曾经为真，后来被更新 | "住在波尔图"（后来搬了） |
| 错误 | 从来不成立：被用户纠正，或推断被否认 | "我没说过要辞职"；A+B→E 被否认 |
| 无法确认 | 有相关证据，但证据本身定不了 | 计划没有结果；转述；冲突未澄清；说得含糊 |
| 没说过 | 记录里根本没有 | 问从没聊过的事；问题带着错误前提 |

现状：基线把每条消息平等地存进去，按相关度返回最多 100 条，这几种情况在读出时长得一模一样。实测返回条数一多，拒答题从 65 分掉到 35 分：回答模型把"沾边"当成了"知道"。

## 1. 原则

1. **原文是唯一权威，原文之上全是投影。** SB、LCE 的线、治理字段都是编译或推导的产物，都可能理解错、可以纠正：纠正产生新的不可变状态，旧状态保留、可审计、可回放。只有原文不可改、不可删。原文丢失时，投影保留并标灰，不隐藏。
2. **时间才是确定性。** 一件事发生了，状态才锁定；计划、意图、承诺说得再确定也没发生。
3. **时间流逝不构成发生的证据。** 计划的时间过了，冻结的是"当时有过这个计划"，不是"它发生了"（4.2 节）。
4. **推断可以回滚，原文和历史不删。** 推断被证伪就撤销，留下拒绝记录；有新证据可以重新评估（3.3 节）。
5. **不推断自己没见到的。** 只基于已到达的内容，没有未来函数。
6. **一次推理，不付两次钱。** 指的是对话本身的理解推理：在线时 Body 回复用户的那次推理顺带产出 SP；之后切 SB、连线是再次推理确认，但复用这段对话仍在上下文里的 KV 缓存，以很低的成本整体理解上下文再切分。它不是说"每 20 条消息必须在一次调用里填完所有字段"。测试集没有一句接一句的对话推理，可以整体读取再切分、归类（成本控制见 4.7 节）。
7. **读出只做减法和事实标注，不加指令、不合成答案**（第 5 节）。

## 2. 时间：只有双时间轴

| 时间 | 含义 |
|---|---|
| `occurred_at` | 消息发生时间：这条原文在历史上的位置 |
| `known_at` | 发现时间：系统什么时候得到、可以使用；派生状态有自己的 `derived_known_at` |

- 实时对话里两者相同，只在补录旧记录时分开。不加第三个时间（不要 `event_time`）。
- **内容里说到的时间是内容，不是时间轴。** "十年前去过冰岛"里的时间原样留在内容里。
- 数据源没给消息时间时，系统**不编造消息时间**：只知道先后顺序，读出和编译输入里都不写时间。但接收时间就是 `known_at`，晨昏线以它为"当前"：内容里说的 2024 年的事在 2026 年收到时，已在当前之前。
- 一切"最近""到点"都按消息时间算，不按系统时钟，回放是确定的。

## 3. 状态的三层

三层互相独立，任何一层的变化都不能推出另一层。

### 3.1 事实状态：由证据驱动

- 认知方式复用核心已有的 `EpistemicStatus`（断言、计划、不确定、假设、反事实、转述、未知）和 `TemporalScope`，由编译器在 SB 级给出。不新造枚举。
- 关系复用核心已有字段：取代（`supersedes_memory_id`，表示过时）、矛盾（`contradicts_memory_ids`，未澄清时两边都有效，澄清后转为取代）、支撑。
- 计划和结果不新增关系：它们是同一条线上的先后步骤（第 4 节）。

### 3.2 推断状态：由 LCE 负责

`UNRESOLVED` 是 LCE 对自己推断的判断（"这几块证据该连成哪种结构，我定不下来"），不是对事实的判断，不能拿来当"无法确认"用。一条线可以很确定（"用户计划明年去葡萄牙"），而"去没去"本身仍无法确认。

### 3.3 被否认的推断：撤销、保留、可重评

以 A + B → E 为例：

| 情况 | 处理 |
|---|---|
| 用户明确否认 E | 撤销 E 当前的有效性，依赖它的结构回到上一个仍有依据的状态；写入拒绝记录"A + B 不支持 E"；同样的证据下不得再生成 E |
| 后来出现新证据 C | A + B + C → E 可以重新评估，旧拒绝记录保留 |
| 回看历史 | 被否认的 E 仍可审计；按知道的时间回放，否认之前它仍可见 |

- **拒绝记录只有一处，在 MR-Mem。** MR-Mem 是编译权威，LCE 是它的编译产物；编译时把相关拒绝记录和候选线一起交给编译器，精确匹配作最后一道闸（LLM 换个说法就能绕过纯精确匹配）。
- 回滚的是当前有效的认知；否认本身作为新事实追加进历史，不抹去任何记录。

### 3.4 注意力：这次编译有没有读到

- 注意力只决定编译时编译器能看到哪些已有的线（4.6 节），**不改变事实和推断**。"衰减只改变注意力，不改变真实性。"
- 休眠就是这次没被读到。睡了一年的线读出时照样能被查询召回，它不会因为睡着就被当成放弃，也不会被当成已经发生。

## 4. 核心模型：LCE 的线（用户 2026-10-14～15 讲解定稿）

### 4.1 概念层次

```
原文（唯一权威）
  └─ MR-Mem 编译 → SB（投影最低层：事件被切成的点）
       └─ LCE（整体概念），三部分并列：
            ├─ Thread：现在进行时
            ├─ Path A：过去完成时
            └─ Path B：由过去推出的未来时可能性（可证伪）
```

- LCE 是总称，Thread、Path A、Path B 都属于 LCE。说整体写"LCE"，说某一部分写明是哪一个；不要用"LCE"代指 Path A。
- **SB 是点：** 一件事被切成多个最小完整单元（做了什么、为什么、观察到什么、怎么想、可能后果）。不为此造字段（不加 facet）。检索到 SB 不等于恢复了事件的演进逻辑。
- **SB 天然跨很多个 turn。** SB 是"避免断章取义的最小语义单位"：一个提问、对它的回答、紧接着把意思补完整的追问和澄清，合起来才是一个完整的意思（像一次群聊整理里的一个 Turn：几个人十几条消息讲完一件事的一步）。"一个大段落可以切成多个 SB"只是一面；另一面是一个 SB 本来就跨多个 turn。不要把问和答、一句和它的补充切成原子碎片。
- **SB 保留谁说的、谁接了谁的话、谁没有搭理。** 互动信号本身是信息（用户只接了某人的话、对别的暴论不予理睬），不能把所有人的观点放成同一权重。
- **Thread 和 Path A 负责把点串成线**，这是编译时的显性工作。Path B 从已有的线里发现跨经历的连贯假设。

### 4.2 只有一种结构：线；Thread 与 Path A 是晨昏线的两侧

- **Thread 和 Path A 不是两个容器，SB 不在两者之间"搬家"。** 一个 SB 一出现就在它的线上，变的只是它处在一条随时间移动的晨昏线的哪一侧：
  - 天黑了（已发生、已冻结、改变不了）= Path A，过去完成时；
  - 天亮着（还在进行、还可能改变）= Thread，现在进行时。
- 区分的是时态："我想去葡萄牙"（意图）/"我去葡萄牙"（进行，航班可能延误、改降、返航）/"我去过葡萄牙"（人真的到了，在当下锁定）。
- **一个 SB 在哪一侧，由当前时间决定，不靠谁去改它：**
  - 说的时候就已经发生的：一直在过去一侧。
  - 未发生、有明确时间的（"明天 19:00 吃饭""下午的飞机"）：时间一过就冻结。**这个时间是内容，不是第三条时间轴**：编译器把它按固定格式写进 SB 内容（"明天晚上（2024-05-07 19:00）"），"过没过点"就是拿内容里的这个时间和当前消息时间比较；不另存时间字段。**冻结的是"当时有过这个计划"这件事本身，不管后来发生没有。** 像 git：当时 commit 了"有这个计划"的状态，轨迹已经有了；回溯时看得到之前有过这个计划，再从别的事件知道为什么没发生。"没赶上、改签了"是从这个已冻结的计划继续长出的进行时的线。
  - 未发生、没有时间的（"想买电脑"）：不靠机械规则扫过。它可以是多条分支的起点，只有当后来的内容让编译器读语义判断它已定下来（"旧电脑还能用，不买了"）时才冻结。
- **一个 SB 里同时有已发生和未发生的部分时，编译器切成两个 SB：**"约了明天吃饭"→"约了"（已发生）+"明天吃饭"（未发生，有时间）。
- **决定在说出的那一刻就是已发生的事实**（"因为没预算，决定不买"），带着理由；不挂着等结果。
- **有明确时间的真实世界计划会演化：**发生了什么就如实记下、接着往下长（坐上了 → 东京 → 酒店 → 吃饭；没坐上 → 改签 → 通知客户）。**没发生的就是没发生，不预先穷举可能性**（"平行时空"只是比方，只有真实发生的那条被记录）。

### 4.3 线是 git 式的树，去中心化，永不结束

- **一个步骤可以长出多条分支。** "到了葡萄牙"之后，吃饭、逛街、买东西并列分出去，彼此没有直接联系，但都挂在同一个节点下，属于同一段经历。分支下还可以再分叉。"想买电脑"可以长出：涨价了 / 工资没发 / 没看到喜欢的 / 旧的还能用，各自生长。
- **没有 main。** 每个分支是一个独立的方向，可以一直长大，不需要合并回任何主干。
- **线永不结束，没有"结束"的概念。** 当下事实是否冻结是 Thread 与 Path A 的唯一分界；两者都可以继续发展。子任务做完，是这条分支上的这一步冻结了；它所属的主线（项目到 4 月 15 日）照样在走。编译器不判断"这件事结束了没有"。
- **微观看就是一根带索引的线触发了一条分支**：新分支只挂指向它所生长的那一步的索引作背景，不带前面的全部内容（约什么餐馆和当初怎么赶飞机没有直接关系）。回溯顺着索引往上走，不做全库检索。
- **不同维度的树在 SB 上交汇。** 同一个 SB 可以同时在几条线上（"在里斯本吃了地道葡萄牙菜"既在葡萄牙之旅上，也在饮食偏好上；一个子任务既在项目时间线上，也在它自己的分支上）。
- **长成时间线不是问题。** 时间是逻辑发展的强 alpha 因子，agent 的对话也大多有时间戳；只要不是强行按时间顺序接，同一个 SB 可以同时在时间线和自己的分支上。"接在谁后面"指的是"这一步是在哪一步的基础上发生的"：常常是最近一步，但不强求。
- **维度是线延伸的方向，不是固定的层级。** 对话按时间推进是一个方向，各人的立场与口味是一个方向，事情之间的因果承接是一个方向，Path B 的跨经历关联又是一个方向；同一个点可以同时在几个方向的线上，分支还能再分支、再汇合（两人"爱看电影"的分支在"推荐电影"汇合）。不预设"纵向/横向""话题层/分支层"这类分层；那只是帮助理解的比方。读的时候按尺度取：只看对话推进知道聊了什么，进到一处看大家怎么展开、哪里同哪里不同，读整棵树看到细节。
- **不是每个 SB 都要上线。** 只按语义和逻辑连线，不强求：聊开发时插一句"鸡蛋真好吃"，这个 SB 单独放着。

### 4.4 一件事没有名字；摘要跟着事情走

- 一件事（编译器的 thread）**没有名字**，身份只用代码编号确认。名字当身份，事情一变名字就对不上；当检索，名字定死后事情走远就搜不到（葡萄牙之旅后来改去西班牙和北非）。
- **它是什么、走到哪一步，全在摘要里。** 摘要随事情变化，检索也靠摘要；被取代的旧计划在摘要里写成"已被取代"，不写成当前状态。
- **改了方向仍是同一件事：** 截止日变了、范围收了、目的地改了，都接续原来的线（前提是确认说的是同一件事），否则旧计划会一直挂着，被检索出来制造幻觉。**字面相似不代表同一件事**：不能因为都有"安排"就串在一起。
- 以后又想发展以前定下的事（不买电脑之后又想买），从那个已冻结的旧步骤继续长，在摘要里对照当初的理由；旧步骤不改。
- 过去的步骤只在"对过去的认识"变了时才产生新修订（后来的证据表明当初理解错了、推断被否认、新思路把过去的事重新串联），旧修订保留，历史只追加。

### 4.5 合并：防止过度分叉（暂定，看数据再定）

- 去中心化不等于随便分叉。把本该是一条线的东西拆成多条并列短分支，等于又只把原文拆成 SB、没组成线去理解，语义反而散了。数据越多越严重。
- 暂定触发点（用户 2026-10-15）：同一个节点下挂了几条兄弟短线时检查一次；新开一条线时，与已有线的摘要比较一次，看是否是同一件事换了说法；两条并列线在某个 SB 交汇后，检查能否作为一条线更通顺地理解。合并与否由 LLM 判断；合并是新增一次修订，旧结构保留。
- 反过来也要能分辨"确实是两件事"（冲刺 1 和冲刺 2 是两件事）。

### 4.6 编译时看到什么：KNOWN_LINES

- **编译顺序：先按原文整体理解事件，再切 SB，最后给 SB 分类、连线（用户 2026-10-15）。** 先切 SB 再拿碎片逐个判断，会丢掉整体语义：项目下的子任务被当成互不相关的新事，长成一堆孤立的小树。所以同一次调用里分三步：①读这批原文（连同上下文和候选线）整体，认出它在推进哪些事——接续已有的事，或从已有某一步长出的新事（项目下的新子任务不是"无关的新事"）；②切 SB；③把每个 SB 放进第①步认出的事里，标明接在哪一步之后、是否已发生。
- 接哪条线、从哪一步长出来、是否已发生、哪个进行中的步骤已定下来——都由编译器（LLM）在上下文里读语义判断。**这是显性工作，不用向量互近邻、证据收敛、Pareto 来决定挂线**（那些是 Path B 的工具）。
- 话题开始时，检索把合适的候选放到编译器面前：
  - 线上仍在进行时一侧的步骤（它们是还可能变的）；
  - 最近活跃的事、用这批新内容检索唤醒的事（摘要 + 最新一步），以及相关的已冻结步骤；
  - 相关的拒绝记录。
- 每个候选带一个短编号（T1、N3），编译器用编号指代；编号到代码 ID 的映射和编译结果一起记入日志，可回放。
- 休眠 = 这次没被选进候选；它仍在，读出时照样可被查询召回。

### 4.7 编译窗口与成本（用户 2026-10-15）

- **窗口不能一次读完全部，也不能硬切。** AML 那种几十万到上百万 token 的语料不可能一次读完；上下文太长，模型会生拉硬套产生幻觉。所以有上限，但是**软上限**：到了目标量，往后找最近的**自然断点**收口（会话结束、长时间间隔、一轮来回结束）。只有远大于软上限的安全硬顶是硬的；单条超长输入（一次丢进两篇长文）在文内按章节/段落切，相邻块有重叠，不在整条上一刀两断。
- **自然断点就是一次大的话题切分**（群聊整理里的"阶段一、阶段二"那一层），是最粗一层结构；SB 在段内跨 turn 切出，线在 SB 之间连、可以跨段跨页。
- **没说完的尾巴留到下一窗。** 编译器可以说"最后这几条还没讲完一件事"，这几条不切，带进下一窗一起切；一个 SB 跨窗口边界也不会被拦腰截断。
- **成本靠 KV / 前缀缓存，不靠每窗从头读。** 提示词按"稳定前缀 + 追加"排：最前面是固定的编译说明；中间是该用户的原文，只往后追加（读过的就是缓存前缀，按缓存价计费）；最后才是每次会变的部分（本次要编译的新消息范围、候选线、拒绝记录）。每次全价的只有新消息、末尾那段和输出。这就是在测试环境里复刻在线时"对话留在上下文、编译复用它"的设计。自然断点放在缓存里判断，几乎不增加成本。
- **翻页 = 开新对话 = 压缩。** 前缀累积到软上限并走到自然断点时翻页：新前缀只放固定说明、已有线的摘要和关键步骤（压缩后的状态）、上一页末尾一小段原文作重叠。翻页时机就是"什么时候开新对话、什么时候压缩"的答案。
- 编译时关掉模型的思考模式；输出只要 SB 和连线；**任何字段都可以留空，不为填满格式而过度解读**（不要把随口一句硬套成"关键转折""第一性原理"）。
- 数值（软上限、页大小）用样例定；缓存命中率在接 DeepSeek 官方接口（返回带 `prompt_cache_hit_tokens`）时实测，本地 agy 看不到按 token 计费。

### 4.8 Path B：未来时的可能性

- 从多条线、多棵树的过去时里推出跨经历的连贯假设：看到喜欢的电脑没钱不买 → 点外卖纠结半天选了便宜的 → 每月生活费八千，看起来不是真没钱 → 推测更在意实用和性价比 → 选手机时推荐小米。
- **可证伪**：后来发现用户也很看重便利和美观，这条推断就被证伪或部分证伪，按 3.3 节处理。
- 跨线的交汇点和背景索引就是它要用的关联。LCE 原有的结构发现（互近邻轨迹、证据收敛、Surface、灵感素材）属于这里，第二阶段移植。

## 5. 读出：交给回答方的东西

### 5.1 AML 规则下的边界

| 做法 | 判断 |
|---|---|
| 返回 `[]` | 合法 |
| 合成"记录里没有关于 X 的内容"这样的条目 | **不做**：等于在 Search 里生成拒答题的答案 |
| 写入时算出、与查询无关的状态标注（"计划，未确认是否发生"） | 倾向可以：它是记忆本身的属性 |
| 读出时针对某个查询临时生成的文字 | 不做 |
| 写"请以新值为准"这类指令 | 不做，以免被当成提示注入 |

### 5.2 以减法为主，标注从严

1. 主手段是选择返回什么：被否认的推断不返回；被取代的旧值只跟在新值后面；优先返回编译好的线，而不是 100 条原始消息。
2. 标注只用极少的英文固定短语，每一种单独做消融实验，在拒答题上掉分的就删。
3. 数据源给了消息时间才写时间，没给就只保留先后。

### 5.3 按问题取树上的局部投影

- 查询本身就是唤醒线索。睡着的线和醒着的线平等竞争。
- **一条线交出的是编译好的线（摘要 + 按顺序的关键步骤），不是零散的 SB，也不是整条线的全文。**
- **按问题取树上对应的部分：**问"葡萄牙玩得怎么样"，整棵树都是证据，读整棵树这一层的概括；问"吃得怎么样"，只取吃饭那条分支；问"为什么去"，取根部那几步。
- 每一步标明它在晨昏线哪一侧（已发生 / 进行中 / 计划过、结果未知）。

### 5.4 "没说过"和"无法确认"：实测教训

- 向量余弦、通用重排都分不开"答得上"和"拒答"：它们判断的是"是不是同一件事"，不是"这个具体事实在不在"。
- 所以不用相关度分数逐题做门槛；返回条数用全局 K，靠端到端测试定（P1 上 K=20/50/100 成绩接近，K 不是大杠杆）；"没说过"主要靠写入侧的精炼减少噪声。

### 5.5 双向索引

- 向下（投影 → 原文）：每个投影都能追到支撑它的原文，用于回溯验证。
- 向上（原文 → 投影）：融合检索召回原文后，顺着反向索引找到由它编译出的 SB 和所在的线，一并交给读出。
- 一条线同时满足"它引用的原文被这次查询召回"和"它本身与查询相关"，两路互相印证，置信度更高。

### 5.6 计分看回答，不看召回

AML 成绩是平台答题模型读我们的列表后答对与否。R@k（只认原文）只是诊断，不能用来判断 LCE 有没有用。LCE 的预期优势在跨对话、前后变化的关系题（知识更新、事件顺序、时间推理、跨会话推理、偏好演变），要按题型拆开看。

## 9. 容易犯的错（每一条都犯过）

| 错误理解 | 正确理解 |
|---|---|
| Thread 和 Path A 是两个容器，冻结了就把 SB "移交/搬进" Path A | 只有一种结构：线。Thread/Path A 是晨昏线两侧，SB 一直在线上，只是所处一侧随时间变 |
| 线会"结束"、要标 done、整条线结束后移交 | 线永不结束，没有结束的概念；子任务冻结 ≠ 主线结束 |
| 有时间的计划没发生就一直挂着，或时间一过就当它发生了 | 时间一过冻结的是"当时有过这个计划"，发没发生由后续事件说明 |
| 没时间的意图被"下一步"机械扫过 | 它可以是多条分支的起点；靠编译器读语义判断已定下来才冻结 |
| 线是单线程（贪吃蛇） | git 式的树：分叉、并列、交汇，没有 main |
| 每个 SB 都要挂线 | 只按语义和逻辑连线，接不上的单独放 |
| 线有名字，名字不能改 / 按名字匹配 | 没有名字，只有编号；语义在摘要里，摘要跟着事情走 |
| 字面上都有"安排"就是同一件事；改了截止日就是新的事 | 反过来：看是不是同一件事；改方向仍是同一件事 |
| 编译器的挂线要经过向量/证据收敛认定 | Path A/Thread 是显性工作，LLM 在上下文里判断；收敛属于 Path B |
| "LCE" = Path A | LCE 是总称，三部分并列 |
| 重新想买电脑 = 在旧线上出新修订 | 事情继续发展：从冻结的旧步骤继续长；只有对过去的认识变了才修订过去 |
| 树长成时间线是坏事 | 时间是强 alpha 因子，不是问题；只是别强行按时间接 |
| 读出给零散 SB，或者把整条线全文堆进去 | 交出编译好的线，按问题取树上对应的局部 |
| 原文丢了就把投影藏起来 | 投影保留、标灰、降置信度 |
| 编造消息时间（用编译时的本机时间） | 数据源没给时间就只保留先后 |
| 给计划单独加 `time`/`due` 字段存起来 | 那是第三条时间轴（`event_time` 换了个名字）。只有双时间轴；说到的时间是内容，写进 SB，比较时读内容 |
| 自己造概念（"工作集"）、造第二套账本 | 先映射到已有架构；拒绝记录只在 MR-Mem 一处 |
| 用一堆条文规则（编号、默认接上一块、候选数）让模型逐条填，出偏差再加规则 | 调教陷阱。让模型按原文整体理解去做；规则越少越好；先定"理想结果长什么样"作参照再试 |
| 预先判断大事小事、主线分支，再把点塞进去 | 先把点放好，再在邻近的点之间判断连不连；主线分支是连出来的结果 |
| 把"对话里接着说的"当成"事情上接着发生的" | 按语义和逻辑连；话头的承接不等于事件的承接 |
| 二元选择（按话题切还是按人切）；或把"纵向/横向"这类比方固化成数据结构的层级 | 只有点和线；方向/维度从内容里长出来，同一个点可在多个方向的线上，分支可再分支、再汇合 |
| 把 SB 切成原子碎片（问一块、答一块） | SB 天然跨多个 turn，是避免断章取义的最小语义单位 |
| 在 20 条消息的小窗口里逐块编号；或反过来想一次读完全部 | 软上限 + 自然断点收口 + 尾巴留到下一窗；前缀缓存控成本；翻页即压缩 |
| 先切 SB，再拿每个 SB 碎片单独判断属于哪件事 | 先按原文整体理解事件，再切 SB，再给 SB 分类连线 |
| 数据源没给消息时间，就以为"当前时间"不可靠、不能比较 | 接收时间就是 `known_at`（当前时间）；内容说的是 2024 年的事，就在当前之前，按晨昏线冻结是对的。"回到当时看它还在进行"是按 `occurred_at` 回放的另一视角 |

## 10. 已定与待定

**已定：**
- 只用双时间轴，不加 `event_time`，也不以任何别的名字（`due`、`time`）加回来；计划的时间是内容，按固定格式写进 SB，比较时读内容。没给消息时间就不编造。
- 原文之上全是投影，SB 也可以被纠正（新状态，旧状态保留）；只有原文不可改；原文丢失时投影标灰不隐藏。
- 推断可回滚，拒绝记录只在 MR-Mem 一处。
- 第 4 节的核心模型：一种结构（线）；晨昏线；git 式的树、去中心化、永不结束；一件事没有名字；改方向仍是同一件事；不强求上线；Path A/Thread 由 LLM 显性串线，Path B 才用结构发现。
- 一件事由多个小 SB 串成，不加 facet 字段。
- 不合成"没有记录"条目；标注用英文固定短语，逐项消融。
- 休眠 = 这次没进 KNOWN_LINES，不另设状态。
- LCE 移植进 MR-Mem，移植时按本稿审核旧实现。
- SB 跨多个 turn；保留说话人和互动关系；字段可留空，不过度解读。
- 编译窗口：软上限 + 自然断点（即大话题切分）+ 未说完的尾巴留到下一窗；稳定前缀 + 追加以利用缓存；翻页即压缩（4.7 节）。

**待定：**
1. **合并机制的具体规则**（4.5 节），看样例数据再定。
2. **候选每类读多少条**（进行中步骤、最近活跃、内容唤醒），用断线率测定。
3. **读出的具体形态**（5.3 节）实现后先拿样例给用户看。
