# LCE 冻结定义（2026-10-31）

这里是用户已经说明白、已经确认的定义。**冻结就是冻结**：实现、提示词、读出都照这里来，不在实现过程中改。

## 1. SB

- **SB 是在聊的那件事。** 某人提起一件事，以及围绕它的来回，只要话题还在这件事上，一百轮也是一个 SB。例："我吃了早饭 → 吃了什么 → 三明治 → 他不爱吃、喜欢面条 → 我偶尔也吃"是"聊吃早饭"这一个 SB。
- **SB 写的是理解，用句子主干写：** 主语（谁）+ 谓语（做了什么：询问、讲述、解释、建议、决定、给出……）+ 宾语（哪件事）。
- **具体内容不编进 SB：** 吃了什么、谁喜欢什么、数字、步骤、代码、**时间**，原文里都有，原文检索能找到，编一遍不提供增量。
- **SB 的价值在于检索之后。** 原文命中后，顺着索引带出 SB 和 Line，用来理解事情的经过，再去推理。
- 用主谓宾定状补去理解用户的定义，是**启发**，不是逐字套用词性规则（"吃了三明治"里三明治是宾语，不是定语）。

## 2. Line、段

- **Line 由 SB 和承接构成，一直在长，没有终点**（设计稿 §4.3）。Line 没有名字，不去界定 Line（§4.3、§4.4）。
- **段是 Line 上已经长好、成熟了的一截，相当于 Path A 那一截的语义总结。** 段是 Line 的一部分，Line 不是段的一部分。
- 段摘要和"不界定 Line"不冲突：段摘要只写已经成熟、不会再变的那一截，写一次就定下来；不给还在长的部分写概括（§4.4"摘要不能做成吸附一切的全貌"）。
- **段摘要用来辅助检索和局部投影，不是专门用来连接 Line 的。**
- **段摘要的结构：** 前因 - 谁 - 何时 - 做了什么 - 后果。按句子成分就是：状语（前因、时间）+ 主语 + 谓语宾语 + 补语（后果）。粒度参照用户的例子，一天几行，不是逐步记录。
  - 用户的例子："前因：无，消息突然开始。谁：我和对方。何时：对话时间。做了什么：由我提到早饭，引出了一串关于饮食习惯、饮食偏好和期待的对话。后果：因为说到想吃蛋挞，引出了上次葡萄牙之旅的讨论。"
- **段摘要不写具体数值和细节**（用户 10-31）：它是结构性总结，抽象层级比 SB 更高，讲的是一条 Line 的变动过程。**唯一的区分：数值是单纯的数据（起点、目标、参数、测量）还是结果本身。** 结果就是一个数值时，它就是后果，要写：用户让 Claude 优化项目，分数提升了 30%；只写"获得了性能提升"就很荒谬。
- **单独的承接层是多余的。** 话题之间的思想演进没有语义上的边，这是正常的；从哪来、引出了什么，写在段摘要的前因和后果里。
- **编译流程每个窗口 2 次调用：SB 一次，段一次**（用户 10-31 确认）。去掉现在的第二步承接、分段归堆、每个窗口重写摘要。

## 3. 晨昏线：Thread 与 Path A

- 设计稿 §4.5 的定义：**Thread 和 Path A 是 Line 上的两种状态，不是两个容器。** 天亮着、还在进行、还可能变的 = Thread；天黑了、已发生、已冻结 = Path A。晨昏线扫过整张图，同一条 Line 上可以一部分在亮侧、一部分在暗侧。
- 设计稿：决定在说出口的那一刻就已经发生了（暗侧）；有明确时间的计划，时间一过就冻结；没有时间的意图，要等后来的内容定下来（`settles`）。
- 用户 10-31 确认以设计稿为准（当天口头说反了）：赶飞机的例子里，"下午去赶飞机"这个计划已经发生，在暗侧，是 Path A；赶飞机这个行为还没发生、可能会变（取消、堵车没赶上），在亮侧，是 Thread。唯一确定的是时间。

## 4. 时间：双时间轴

- 只有两条轴，而且都是**消息**的时间：`occurred_at` 是消息什么时候说的；`known_at` 是系统什么时候拿到它。不加第三条时间（设计稿 §2）。
- **内容里说到的时间是内容，不是轴。**
- **时间是相对的。** "今天说明天去吃饭"，到了后天回头看，检索出"明天吃饭"的原文却不知道它是哪天说的，就很荒谬。时间推理最有力的依据，就是**原文带着它自己的消息时间**，再加上顺着 SB 和 Line 看到的前后经过。
- 所以：读出里每条原文都标上它的消息时间；SB 不抄写时间细节；SB 和段只带自己首尾消息的时间范围，用来把经过排在时间线上。
- 数据没给消息时间时，不编造。
- 用户原话（冰岛的例子，10-13）："我今天和你说十年前我去了冰岛，那么消息时间就是今天……三年前说过十年前去过冰岛，看起来有三个时间，但是实际上消息时间还是今天……没必要再拆分成原文历史时间和事件发生时间。"（10-15）"你都知道是 2024 年的事情，怎么会不知道这个事件发生在当前时间（消息接收时间）之前呢？"（10-30）"有日期还是要写日期吧，但是重点是……不能把系统导入时间当成真事件时间。"
- 由此：**消息时间只说明这句话什么时候说的，不说明事情什么时候发生。**事件时间从内容里读，以消息时间为基准；永远不把消息时间或导入时间当成事件时间。
- 用户 10-31 的拆解："我今天说（消息时间）三年之前我说（事件时间）十年前去过冰岛（这是事件）。"
  - **消息时间**：今天，2026-10-31，"我今天说"这句话说出口的时间。
  - **事件**：三年之前我说过"十年前去过冰岛"。**事件时间**：三年之前，约 2023 年，"我说过……"这件事发生的时间。
  - "十年前去过冰岛"是事件的内容，里面的"十年前"是相对 2023 年说的。
- **编译只解析一层**（用户 10-31 确认冻结）：以消息时间为基准，把事件本身的时间解析出来，写成"2026-10-31 我说：约 2023 年（三年之前）我说过十年前去过冰岛"，到这里就够了。事件内容里嵌套的时间原样保留，不往下推算（不把"十年前"算成 2013 年）。区分绝对的事件时间需要连续推理，不是解析；多个时间叠在一起时，编译阶段推很容易出错，留给答题模型推理。
- 按句子成分：主语（我）+ 谓语（说）带消息时间；宾语这件事带事件时间，解析一次；宾语里面再嵌套的内容保持原样。
- **原文里的绝对时间是细节**，不往 SB 里抄（用户 10-31）。检索命中原文（如"十年前去过冰岛"）后，反向索引带出编译后的 SB，连同它的消息时间和事件时间，交给答题模型推理。
- **段摘要提供事件时间轴**："前因 - 谁在什么时间做了什么 - 后果"里的"什么时间"是事件时间。
- **消息时间只从原文自带的时间戳里取。** SB 和段都不自己造消息时间。

## 4.1 晨昏线的字段只在记忆侧用（用户 10-31）

- 晨昏线（`when`、`status`、`settles`）是记忆侧自己的判断：哪些事已经确定发生，哪些还在演进。**它和答题无关，不给答题模型看。**
- 答题模型要理解的只和双时间轴有关：消息时间（原文时间戳）和事件时间（SB、段）。
- 所以读出里不显示 `[confirmed; before]`、`[likely; after]`、"（later settled, see …）"这类标记。

## 5. 读出

- 原文命中 → 顺着索引找到 SB → 找到 SB 所在的 Line 和段 → 理解经过 → 推理。
- SB 写理解，细节靠原文：命中的原文要挂在它对应的 SB 下面，并且带着消息时间。
